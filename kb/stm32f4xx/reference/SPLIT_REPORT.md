# Отчёт: разбиение RM0090 на разделы для Qdrant RAG

Дата: 2026-10-14 (v3)

## Что сделано

- Каталог: `rm0090_sections/` — **428 файлов** (3,4 МБ), max 52 КБ + `manifest.json`, `INDEX.md`, `index.json`.
- Источник: `STM32F4xx_Reference_Manual_part1..9.md` (RM0090, 1749 страниц). Цель: RAG-справочник по STM32F407 для агента-кодера.

## Правила разбиения (v3)

1. Главы 1–39; глава 40 (Revision history) и front matter пропущены.
2. Глава → секции `N.M` (заголовки `#`/`##`/`###`/`**N.M**`); секции <1,5 КБ сливаются вперёд в главе.
3. Секции >60 КБ → по регистрам `N.M.K` (регистр + offset + reset + таблица + биты вместе).
4. Любой файл >30 КБ → чанки по `###`-границам; в начало каждого чанка добавлена контекстная шапка `> [RM0090 ch.N §N.M] Title`.
5. HTML-таблицы → markdown, **colspan-дубли ячеек свёрнуты** (строки register map сжаты с ~8К символов до компактных).

## Файлы F42x/43x — НЕ для F407 (`applies_to` в manifest, `not_on_f407` в index.json)

Главы **6** (RCC variant — F407 использует гл. 7), **11** (DMA2D), **15** (DCMI), **16** (LTDC), **29** (SAI), **37** (FMC). 73 файла помечены. При ingestion: не индексировать или фильтровать в retrieval.

## Индексы

- `INDEX.md` — для агента/человека: «задача → глава» (30 рецептов: GPIO, RCC/PLL, low-power, DMA, EXTI, ADC, PWM/dead-time, RTC, I2C/SPI/USART, CAN, USB, Ethernet, FSMC, UID и т.д.) + полная карта глав → файлы.
- `index.json` — машинный: по главам списки файлов с `section`/`title` и флагом `not_on_f407`.
- `manifest.json` — полные метаданные всех 428 файлов (chapter, section, title, bytes, applies_to).

## Рекомендации по ingestion

1. Чанковать ~500–1000 токенов, перекрытие 10–15%; metadata = chapter, section, title, source_file, not_on_f407.
2. Индексировать `INDEX.md` и `index.json` как отдельные документы «index» — они дают агенту маршрут по периферии до погружения в регистры.
3. Фильтровать `not_on_f407 == true` при поиске.
